# 企画書（第1版・2026-10-22）

## 1. ひとことで
**届いたメッセージが本物か詐欺かを、遊びながら見抜けるようになるブラウザゲーム。**

## 2. 誰の、どんな困りごと
- **遊ぶ人：誰でも**【作者】。スマホを使うすべての年代。最初の版は、どの年代にも届く手口から選ぶ。
- **困りごと**：詐欺のメッセージは年々本物に近くなり、「注意しましょう」と言われても、どこを見ればいいか分からない。注意喚起は読まれにくく、怖さだけが残る。
- **このゲームでの解き方**：本物そっくりの練習問題を自分で判断し、間違えたら「どこが違ったか」を印で見せる。読む注意喚起ではなく、**体で覚える練習**にする。

## 3. 新しさ（ほかの注意喚起との違い）
- 怖がらせるのではなく、**遊びで「見抜く目」を鍛える**。
- 結果を点数とタイプで出し、**共有したくなる**作りにして、注意喚起が届きにくい人にも広がるようにする。
- 作者のゲーム作りの経験（遊びの設計・試遊からの調整）と、セキュリティの知識の組み合わせ。

## 4. 最初の版（小さく作り切る）
- 10問。1問ずつ、メールか SMS の画面が出て、「本物」か「詐欺」を選ぶ。
- 答えたあと、見るべき場所（送り主、リンクの URL、急がせる言葉、日本語の不自然さなど）に印を出して解説する。
- 最後に点数とタイプを出し、結果画像を作って共有できる。
- 題材の候補（どの年代にもある手口）：宅配の不在通知、銀行やカード会社を名乗る本人確認、懸賞・当選、知人を名乗る SNS の連絡、サブスクの支払い失敗。本物のお知らせの例も混ぜる（全部が詐欺だと「全部疑う」だけで満点になってしまうため）。

## 5. 作り方（案）
- 画面だけで動く Web サイト。GitHub Pages で無料公開する（サーバーが要らないので、守るべき場所が少なく、費用もかからない）。
- 言語は TypeScript（JavaScript に型を足したもの。間違いに早く気づける）を予定。
- 自動テストを用意し、問題データの形や採点が正しいかを毎回確かめる。

## 6. 安全と倫理の決まり
- 会社・人・ロゴはすべて架空。実在のものをまねない。
- 個人情報やパスワードを入力させない。入力をどこにも送らない。
- 手口と解説は公的機関の公表内容に沿わせ、出典を書く。
- 詐欺の手口を「教える」のではなく「見抜き方」を教える。攻撃の手順や悪用できる文面の作り方は載せない。

## 7. 就活で話せること（作りながら残す）
- 誰の困りごとから始めたか、なぜこの形にしたか。
- 安全のために何をしなかったか（実在の名前を使わない、情報を集めない）。
- 遊んでもらった人数、正解率の変化など、数字で示せる結果。

## 8. まだ決めていないこと
- 作品名（仮題 scam-spotter）。日本語の名前も考える。
- 1回の問題数と、点数のタイプ分けの名前。
- 公開の時期（Private から Public に変えて GitHub Pages で公開する）。
